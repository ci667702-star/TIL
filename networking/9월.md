# OSI 7계층

컴퓨터 네트워크 및 통신을 7개의 레이어(계층)로 표현한 모델이다.

### 1. physical<br>
장치를 연결하기 위한 매체의 물리적인 사항을 정의한다.
- 전압, 주기, 시간, 전선의 규격, 거리 등
데이터를 전달만 할 뿐 전송하려는(또는 받으려는) 데이터가 무엇인지, 어떤 에러가 있는지 등은 신경쓰지 않는다.
주요 단위:Bits(0과 1)
대표적인 장비로는 통신 케이블, 리피터, 허브가 있다. 또한 우리가 인터넷을 사용할 떄 쓰는 LAN, 광케이블, WiFi 신호 같은 물리적인 요소들이 포함된다.

### 2. DataLink<br>
포인트 투 포인트 간 신뢰성 있는 전송을 보장하기 위한 계층이다.
송수신되는 정보의 오류와 흐름을 관리하여 안전한 정보의 전달을 수행할 수 있도록 도와주는 역할을 한다. 따라서 통신에서의 오류도 찾아주고, 재전송하는 기능도 가지고 있다.
맥 주소를 가지고 통신한다. 주소 체계는 계층이 없는 단일 구조로 데이터 링크 계층의 가장 잘 알려는 예로는 이더넷이 있다.
주요 단위:프레임
대표적인 장비로는 브리지, 스위치 등이 있다.(여기에서 MAC 주소를 사용함)

### 3. Network<br>
경로를 선택하고 주소를 정하고 경로에 따라 패킷을 전달해주는 것이 Network 계층의 역할이다.
대표적인 장비는 라우터와 Layer3 스위치(라우팅 기능을 장착한 스위치)이다.
네트워크 계층에서는 신뢰성이 보장되지 않을 수 있다. 많은 네트워크 계층 프로토콜이 안정적인 메시지 전송을 제공하지만, 그렇지 않은 경우도 있다. 또한 네트워크 계층에서는 오류 보고가 필수 사항이 아니므로, 데이터 송신자는 데이터가 성공적으로 전달되었는지 확인받지 못할 수도 있다.

**기능**
1. 패킷 조각화 및 재조립
    - 네트워크 계층은 데이터링크 계층의 크기 제한을 초과하는 대형 패킷을 작은 패킷으로 분할하여 전송하고, 목적지에서 재조립한다.
2. 트래픽 제어
    - 네트워크 계층은 네트워크 혼잡을 방지하고 데이터 흐름의 효율성을 유지하기 위해 네트워크 트래픽을 관리한다.


### 4. Transport<br>
양 끝단의 사용자들이 신뢰성 있는 데이터를 전송할 수 있도록 조율하는 역할을 한다.
데이터 패킷이 손실이나 오류 없이 올바른 순서로 도착하는 것이나 필요한 경우 데이터 패킷을 원활하게 복구하는 것에 초점을 맞춘다. 
데이터 전송을 위해 포트를 사용한다.
일반적으로 사용되는 프로토콜은 TCP와 UDP가 있다.
주요 단위:세그먼트
대표적인 장비로는 게이트웨이, 로드밸런서가 있다.

**기능**
1. 서비스 포인트 주소 지정
    - 전송 게층 헤더를 연결하여 메시지가 올바른 프로세스로 전달되도록 한다.
2. 흐름 제어
    - 전송 계층은 데이터 오버플로를 방지하고 네트워크에서 상호 작용하는 두 장치간의 데이터 전송 속도를 관리하여 송신 장치가 적절한 속도로 수신 장치로 데이터를 전송할 수 있다.
3. 멀티플렉싱
    - 전송 계층을 사용하면 여러 네트워크 애플리케이션이 동일한 연결을 동시에 사용할 수 있다.

### 5. Session<br>
세션 계층은 두 장치 간의 연결을 시작하고 종료하며, 리소스가 과도하게 사용되거나 낭비되지 않도록 제어한다. 또한 웹 회의 환경에서 오디오 및 비디오와 같은 관련 데이터 스트림 간의 세션 연결 및 해제를 위한 프로토콜도 설정한다. 따라서 세션 계층은 원격 프로시저 호출을 활용하는 네트워크 환경에서 명시적으로 구현되는 경우가 많다. 

**기능**
1. 동기화
    - 데이터 스트림이 적절히 동기화되도록 하며, 복구 지점을 처리한다.
2. 세션 복구
    - 세션 계층은 네트워크 문제로 인한 세션 장애 발생 시 연결을 재설정한다.

### 6. Presentation<br>
서로 다른 시스템 간에 번역을 담당하는 계층이다.(표현 방식을 결정) 암호화, 복호화, 압축, 인코딩 등의 작업을 수행한다.
SSL/TLS 프로토콜, JPEG 프로토콜, MPEG 프로토콜(동영상 압축용)을 지원한다. 또한 애플리케이션 계층이 네트워크를 통해 데이터를 전송할 수 있도록 해당 데이터를 적절한 형식으로 변환한다. 그러한 역할을 하기 때문에 구문 계층(syntax layer)이라고도 불린다.

또한 수신 메시지가 프로토콜 스택을 따라 상위 계층으로 캡슐화 해제 과정에서는 포맷 변환 및 데이터 변환이 반대로 수행되는 경우도 있다. 이러한 경우에는 발신 메시지는 캡슐화 중에 지정된 형식으로 변환되고, 수신 메시지는 캡슐화 해제 중에 역변환을 거친다.

**기능**
1. 데이터 변환
    - 발신 메시지가 프로토콜 스택을 따라 송신자에서 수신자로 이동하면서 캡슐화되는 과정에서, 데이터를 적절한 형식으로 변환한다.
2. 데이터 암호화 및 암호 해독
    - 안전한 전송을 위해 데이터를 암호화하며, 수신 시 이를 해독한다.
3. 데이터 압축
    - 전송을 위해 데이터 스트림의 크기를 줄이고, 수신 시 사용을 위해 압축을 푼다.

### 7. Application<br>
최상위 계층으로, 사용자 애플리케이션과 직접 연결되어 있다. 이 계층의 주요 역할은 사용자 애플리케이션이 네트워크 서비스를 원활하게 이용할 수 있도록 인터페이스를 제공하는 것이다.

# DNS
DNS는 도메인 이름을 IP로 변환해주는 시스템이다. 사용자가 웹 브라우저에 도메인을 입력하면 DNS가 IP 주소를 찾아 연결해준다.

### Domain Name
인터넷상에서 웹사이트나 서버를 식별하기 위해 사용하는 인터넷 주소이다. IP 주소는 기억하기 어렵기 때문에 영문이나 한글로된 인터넷 주소인 도메인을 사용하고 있다. 
인터넷상에서 사용되는 도메인은 전 세계적으로 고유하게 존재하는 이름이며 정해진 규칙 및 체계에 따라야 하며, 임의로 변경되거나 생성될 수 없다.

## DNS 서버
#### 기지국 서버
인터넷을 설치 시 각각의 통신사가 있다. 그 각각의 통신사마다 DNS 서버가 존재한다.
URL에 Domain Name을 입력했을 때 해당 IP를 찾기 위해 가장 먼저 찾는 DNS 서버이다.

#### RootDNS 서버
기지국 DNS 서버에 해당 도메인에 대한 IP 주소가 없을 때에 Root DNS 서버에 물어보게 된다. Root DNS는 최상위 DNS 서버로 해당 DNS 부터 시작해서 아래 딸린 node DNS 서버에게로 차례차례 물어보게 되는 구조(트리 구조)로 짜여져있다.

#### TLD 서버
DNS 계층 구조에서 최상위 도메인은 루트 영역 다음의 첫 번째 중단점을 나타낸다. 간단히 말해서 TLD는 도메인 이름의 마지막 마침표 뒤에 오는 모든것이다.
TLD는 DNS 조회 프로세스에서 중요한 역할을 한다. 캐시 되지 않은 모든 요청의 경우 사용자가 도메인 네임을 임력하면 DNS 확인자는 브라우저 창에서 TLD 서버와 통신하여 검색을 시작한다.

**종류**
- .com 영리 사업체용
- .gov 정부 기관용
- .uk 영국의 도메인용
- .org 비영리 기관

### 기본 동작
1. 도메인 주소를 이용한 사용자의 요청
2. DNS로 해당 도메인에 대한 IP 주소 질의
3. 요청한 도메인 서비스 IP 주소 응답
4. 사용자 접속 완료

# DHCP(Dynamic Host Configuration Protocol)
동적으로 호스트를 설정하는 규약이다. 
호스트의 IP 주소와 각종 TCP/IP 프로토콜의 기본 설정을 클라이언트에게 자동으로 제공해주는 프로토콜이다.
- 네트워크 안의 컴퓨터에 자동으로 네임 서버 주소, IP 주소, 게이트 웨이 주소를 할당한다.
- 해당 클라이언트에게 일정 기간 임대해주는 동적 주소 할당 프로토콜이다.
네트워크에 사용되는 IP 주소를 DHCP 서버가 중앙 집중식으로 관리하는 클라이언트/서버 모델을 사용한다.

# Monitoring
### 목적
사후 대응에서 사전 예방적 접근으로 전환하여 시스템 가시성을 확보하고 안정성을 높이는 것이다.

### 중요한 이유
사후 대응 중심의 문제 해결 방식에서 벗어나 사전 예방 중심의 접근 방식으로 전환할 수 있도록 한다. 이는 분산된 클라우드 기반 아키텍처 전반에 걸쳐 지속적인 가시성을 제공한다.

### 장점
1. 문제 탐지/해결 속도 향상<br>
    - 전체 기술 스택 전반에서 지속적으로 추적하여 오류, 성능 저하 및 장애를 발생 즉시 탐지한다. 예를 들어 마이크로서비스에서 갑자기 오류가 발생하면 모니터링 툴이 경고를 트리거하여 사용자에게 영향이 미치기 전에 조사하고 해결할 수 있도록 한다.
    
2. 시스템 신뢰성 향상<br>
    - 정상적인 임계값 범위 내에서 운영되도록 보장한다.
    - 모니터링 툴은 경고 및 자동화 설정을 간소화하여 작은 문제가 다운 타임으로 이어지는 것을 방지한다.
    - 소프트웨어 배포가 빈번한 환경에서는 매우 중요하다. 
    
3. 보안 및 규정 준수 강화
    - 인증 시도, 액세스 로그, 네트워크 트래픽 및 비정상 행동 패턴 추적과 같은 보안 중심 실무가 포함된다. 이러한 기능은 DevOps 팀이 보안 위협을 실시간으로 탐지하고 대응하는 데에 도움을 준다.
    - 시스템이 안전하게 정책에 따라 운영되고 있음을 입증하는 감사 추적을 제공하여 기업이 규제 준수를 유지하는 데 도움을 준다. 
    

## 유형
### 인프라 모니터링
애플리케이션을 지원하는 서버, 네트워크, 데이터베이스, 가상 머신, 클라우드 서비스, 운영 체제 및 디스크 스토리지 플랫폼에 중점을 둔다. 이 인프라 모니터링의 목표는 컴퓨팅 네트워크의 백엔드가 예상대로 작동하도록 보장하고, 이상 징후가 최종 사용자에게 영향을 미치기 전에 이를 발견하는 것이다.

CPU 사용량, 메모리 사용량, 네트워크 처리량, 지연 시간 및 가동 시간과 같은 지표를 수집하낟. 그 다음 해당 정보를 중앙 집중식 모니터링 플랫폼으로 전공하여 데이터를 저장, 분석 및 시각화 할 수 있도록 한다.

### 네트워크 모니터링
라우터, 스위치, 방화벽, 로드 밸런서, VM, 컨테이너 및 클라우드 워크로드 간의 데이터 흐름을 추적하여 데이터 전송을 지연시킬 수 있는 연결 문제나 잘못된 구성 상태를 감지한다. 이러한 정보는 CI/CD 파이프라인과 사고 관리 워크플로에 전달되어 실시간 데이터를 기반으로 자동 경고 및 롤백을 설정할 수 있도록 한다.

### 보안 모니터링
시스템, 애플리케이션 및 파이프라인에서 보안 취약점과 잘못된 구성을 지속적으로 추적하는 것을 의미한다. 지속적이로 자동회된 감시로 전환될 수 있게 한다.
툴은 텔레메트리 모니터링과 취약점 탐지, 액세스 모니터링, 규정 준수 검사와 같은 보안 제어를 결합한다. 이를 통해 보안 제어를 CI/CD 및 런타임 환경에 통합하여 소프트웨어 수명 주기 전반에서 보안 위협을 탐지하고 대응할 수 있다.

## 종류
### ps(Process Status)
- 시스템에서 실행중인 프로세스의 상태를 보여준다.
- 프로세스 ID, 사용자 ID, CPU 사용량, 메모리 사용량 등 다양한 정보를 포함할 수 있다.
- 특정 프로세스를 모니터링 하거나 시스템의 전반적인 상태를 파악하는 데에 유용하다.
### top
- 시스템의 동적인 뷰를 제공한다.
- 시스템 성능의 전반적인 개요를 한 눈에 볼 수 있게 해준다.
- 사용자가 프로세스를 관리할 수 있게 인터페이스를 제공한다.
### Grafana
- 데이터 시각화, 모니터링 및 분석을 위한 오픈 소스 플랫폼이다.
- Prometheus, Elasticsearch, InfluxDB 등과 같은 다양한 데이터 소스를 지원한다.
- 대시보드를 통해 데이터를 시각적으로 표현하고, 경고를 설정한다.
### Zabbix
- 네트워크와 서버의 상태를 모니터링하기 위한 오픈 소스 도구이다.
- 성능 모니터링, 네트워크 모니터링, 서버 상태, 온도 모니터링 등 다양한 기능을 제공한다.
- 실시간 모니터링과 로그 분석, 에측 분석 등 고급 기능을 제공한다.
